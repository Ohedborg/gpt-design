# GitHub-backed libraries

Connect an existing GitHub repository (with an initial commit) and a root folder, usually `design-systems`. Do not select an unrelated repository or upload systems based on their recency. `connect_library` accepts payload `{repository: "owner/repo", folder: "design-systems", branch: "main"}`. An empty branch uses the repository default. A new repository can be created through authorized GitHub tools or GitHub CLI, then connected.

Private repositories and publishing use the local GitHub CLI sign-in (`gh auth login --hostname github.com`) or the explicitly configured `GPT_DESIGN_GITHUB_TOKEN` environment variable. The chat's GitHub connection cannot be extracted or reused as a runtime credential. Never request a token pasted into chat or print stored credentials. Public repositories can be read without sign-in. The server contacts only `https://api.github.com` and refuses redirects with credentials. GitHub Enterprise endpoints are not supported in this release.

`sync_library` retries queued initial uploads to their original destination and downloads published snapshots, checks archive and file hashes, preserves edited local drafts, and returns the last successful sync time or an error. Opening/listing the library checks at most once per minute; the studio also checks every minute while visible and on return to the window. There is no manual Sync now step. The explicit sync tool remains available for recovery and always checks. No background service is required, and an already open task retains its pinned version. Cached content remains usable offline but must be described as cached, not verified latest.

Adding a new system to a connected library automatically freezes and uploads version 1. If upload fails, `pendingUpload` records the original destination, version and error; automatic library checks retry it, without including any later draft edits. A waiting upload cannot move to a different connected repository or publish a subsequent version. Existing local systems are not retroactively uploaded on connection.

`publish_system` writes each later version immediately to the connected repository; the studio identifies that destination before publication. The commit includes a catalog update, readable tokens and guidelines, and complete versioned ZIP archives of source, assets and previews. Each system has its own folder and release numbers. The first shared publication includes existing local releases of that selected system. Drafts are local until published. This does not synchronize edits back to an upstream import such as figma/sds, update Figma, or change generated websites.

Repository write permission is checked before shared edits and publishing. Readers receive read-only shared systems. GitHub branch rules still apply; failures leave the local published pointer unchanged. Concurrent publication is rejected instead of force-pushing. If another publisher has advanced the same system, sync and review the newer release before using `start_from_latest`; the replaced draft is copied to local history. Rollback creates a new shared version and preserves both prior versions and the working draft.

Published folders contain `catalog.json` at the library root and `<system-slug>-<id-prefix>/system.json`, `tokens.json`, `tokens.css`, `guidelines.json`, and `releases/<version>.zip`. A library connection lives beside local systems in `github-library.json`; it contains repository details and sync status, never credentials. Keep credentials and local configuration out of the repository. Downloads are pinned to one commit. Existing publication hashes cannot be replaced through the plugin; repository administrators can still rewrite Git history outside it.

This edition uses GitHub repository-level access, not per-folder tenant isolation or ChatGPT workspace membership. Use separate private repositories when audiences must be isolated. Disconnecting retains local copies and disables editing of shared systems until their library is reconnected. Archives support up to 40 MB compressed, 128 MB expanded, 20 MB per file and 6,000 files. Large compiled bundles may require a future artifact-storage backend.
